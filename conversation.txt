whare are some functionalities that are missing in it? or ui experiences
While FindSomething is excellent for passive extraction, its development has historically focused purely on regex-matching raw text. As web development architectures have shifted toward heavily obfuscated single-page applications (SPAs), users and security researchers have noted several structural and user experience (UX) gaps.
Here are the key functionalities and UI experiences currently missing in the tool:
1. Missing Functional Capabilities
JavaScript Deobfuscation and Un-Minification: Modern web applications bundle and minify their JavaScript using tools like Webpack, Vite, or Terser. FindSomething reads this minified code exactly as-is. It lacks a built-in "Pretty Print" or abstract syntax tree (AST) parser to un-minify or format complex scripts, meaning endpoints buried inside heavily packed variable wrappers can occasionally be missed by raw regex.
Source Map Parsing: Many modern frontend deployments accidentally expose .js.map files. A major missing feature is the ability to automatically look for, pull down, and reconstruct the original, uncompiled backend directory structure from these source maps to map endpoints back to their exact original source files.
Active Fuzzing / Direct Testing Interface: FindSomething is strictly a passive scanner. It collects information but does not let you interact with it directly. You cannot right-click an extracted endpoint to change parameters, test for an authentication bypass, or perform a direct custom "Fetch" request to see what payload returns. You must copy the data into an external tool like Postman or Burp Suite.
Live Traffic Interception: It maps strings discovered in the static files, but it doesn't effectively intercept dynamic, runtime XMLHttpRequests (XHR) or Fetch API requests being generated by the application on the fly.
2. Missing User Experience (UX) Enhancements
No Global Search / Dynamic Filtering: While it organizes findings into clean tabs, it lacks a master Ctrl+K search bar to let you quickly filter down results across all tabs. If a site pulls up 500 endpoints and 100 subdomains, you have to scroll through them manually or rely on Chrome's native browser page search.
Lack of Bulk Export Formats: The UI only supports basic text copying or a flat dump. It misses native configuration setups to format the extracted endpoints directly into structured schema models like an OpenAPI/Swagger JSON blueprint, a Postman Collection, or a clean CSV file sorted by domain authority.
No Persistent Diffing or State Management: If you browse through multiple pages of a web application, the tool doesn't keep a persistent session history. If you refresh the tab, your previously mapped endpoints disappear. It lacks a timeline view or a "Diff" tool to compare what subdomains were found on Page A versus Page B.
No "Scope" Lockdown: You cannot easily white-list or black-list specific domains within the configuration. As a result, the tool frequently catches noisy, irrelevant third-party trackers, analytics endpoints (like Google Analytics or Mixpanel), and CDN URLs, cluttering your target view.
Comparison: FindSomething vs. Modern Alternatives

Source Maps	Ignored	Automatically downloaded and mapped
Data Interaction	Read-Only	"Send to Repeater" / Custom Fetch Testing

3. Implementation Code Examples
Python Implementation
Using the standard requests library to fetch and iterate through found subdomains:
python
import requests

def fetch_subdomains(target_domain, api_key):
    url = "https://c99.nl"
    params = {
        "key": api_key,
        "domain": target_domain,
        "json": 1
    }
    
    try:
        response = requests.get(url, params=params)
        data = response.json()
        
        if data.get("success") == True:
            # Safely navigate their standard response dictionary structure
            subdomains = data.get("subdomains", [])
            for sub in subdomains:
                print(f"Found: {sub['subdomain']} (IP: {sub.get('ip', 'N/A')})")
        else:
            print(f"API Error: {data.get('error', 'Unknown error occurred')}")
            
    except Exception as e:
        print(f"Connection Failed: {e}")

# Usage
fetch_subdomains("example.com", "YOUR_ACTUAL_API_KEY")
Use code with caution.

Using modern asynchronous fetch to retrieve the payload:

async function getSubdomains(targetDomain, apiKey) {
    const url = `https://c99.nl{apiKey}&domain=${targetDomain}&json=1`;
    
    try {
        const response = await fetch(url);
        const data = await response.json();
        
        if (data.success) {
            console.log(`Discovered ${data.subdomains.length} subdomains:`);
            data.subdomains.forEach(item => {
                console.log(`-> ${item.subdomain} [Cloudflare Protected: ${item.cloudflare || 'No'}]`);
            });
        } else {
            console.error("API Rejected Request:", data.error);
        }
    } catch (error) {
        console.error("Network or parsing error:", error);

}

Important Developer Safeguards & Limits
Response Format: Ensure you always pass the JSON variable. If left out, the API defaults to returning a flat HTML string with <br> tags separating the subdomains, which breaks native array parsers.
Key Protection: Never hardcode your C99 key inside client-side code (like frontend React or pure browser extensions). C99's firewalls dynamically suspend keys that generate leaks or show concurrent requests from vastly different geographic IPs. Always proxy requests through your own backend server.
Timeout Handling: Subdomain mapping scans can take anywhere from a few seconds to a full minute depending on if the realtime flag triggers deep recursion. Set the network request connection timeout window in your project to at least 60 seconds to prevent premature socket drops.

but how this works to get subdomains? https://c99.nl
Under the hood, platforms like C99.nl map out subdomains using a combination of Passive Reconnaissance (OSINT) and Active DNS Verification. Instead of hacking into a server, the tool gathers public pieces of data left across the internet infrastructure to build a complete architectural picture of a domain.
Here is exactly how the technical process works behind the scenes when you submit a domain scan:
1. Scraping Certificate Transparency (CT) Logs (Passive)
Whenever a company creates a subdomain that uses HTTPS (like ://example.com or ://example.com), they must issue an SSL/TLS certificate for it.
By law, all certificate authorities (like Let's Encrypt or DigiCert) must log every issued certificate in a public, immutable ledger called a Certificate Transparency Log.
C99's backend continuously monitors or queries these global public CT logs.
Even if a company hides a subdomain from their main website, the moment they secure it with an SSL certificate, it becomes permanently visible in these logs.
2. Aggregating Public DNS Datasets (Passive)
The scanner doesn't just check the live internet; it maintains a massive historical database of the web. It aggregates data from multiple open-source intelligence (OSINT) sources and massive internet-mapping projects:
Forward DNS Databases: Utilizing massive, pre-computed databases of known DNS records (like Project Sonar or Rapid7 OpenData).
Search Engine Scraping: Parsing search engines (Google, Bing, Baidu) using advanced indexing queries to see what subdomains have been crawled and indexed publicly in the past.
Threat Intelligence Feeds: Gathering historic domain records shared by security platforms.
3. Active DNS Resolution & Dictionary Fuzzing (Active)
To find subdomains that might not be indexed or logged anywhere yet, the backend uses active enumeration:
Dictionary Attacks: The scanner runs through a text file containing hundreds of thousands of common subdomain prefixes (e.g., test, admin, api, vpn, mail, staging, portal).
Mass DNS Resolvers: It pairs this dictionary list with ultra-fast, automated DNS query pipelines. It blasts thousands of requests per second to public DNS resolvers (like Cloudflare's 1.1.1.1 or Google's 8.8.8.8) asking: "Does ://target.com point to a real IP address?"
If the DNS server returns an A or CNAME record, the scanner marks it as a live, valid subdomain.
4. Analyzing Network Routing (Cloudflare & IP Checks)
Once a list of subdomains is aggregated, C99 runs a final verification check on each one:
IP Lookups: It resolves the domain to its current hosting IP address.
Cloudflare Detection: It inspects the network headers and IP blocks to check if the subdomain is hidden behind Cloudflare's proxy network or if it directly exposes the origin server's real IP address.
Why Companies Can't Easily Hide This
This is why subdomain finders are so effective for bug bounty hunters and developers. Because DNS records and SSL certificates must be public for the global internet to route traffic to them, tools like C99 simply collect these mandatory public footprints and organize them into a clean, searchable interface.

does c99 have a desktop app or free source codes?
No, C99.nl does not provide an official desktop application or publish its proprietary source code. The platform runs strictly as a closed-source, cloud-based SaaS (Software as a Service) to protect its backend infrastructure, optimization algorithms, and massive curated historical databases from being copied or abused.
However, C99 does provide an official command-line interface (CLI) tool for terminal use, and because the underlying mechanics of subdomain discovery are well-known, there are completely free, open-source alternatives that do exactly what C99 does.
What C99 Offers Instead
The Official C99 CLI Tool: While not a graphical desktop app, C99 hosts an official repository for a dedicated Command Line Tool. It allows you to tap into their scanning engine directly from your terminal loop, provided you hook it up to your C99 account API key.
The Free Web Interface: You can use the core functionalities of the scanner completely free of charge directly via your web browser on their main hub, though it is bound by daily rate limits and web-based queues to prevent scraping.
Free, Open-Source Alternatives (Get the Source Code)
